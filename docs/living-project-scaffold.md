# Living Project Scaffold - Implementation Notes

**Date**: 2025-01-27  
**Purpose**: Documentation of schema changes and implementation details for the Living Project system.

---

## Schema Changes

### New Enums

**ProjectIntent** (`prisma/schema.prisma`)
- `PAST` - Completed/historical projects
- `ACTIVE` - Currently in progress
- `FUTURE` - Upcoming/planned projects

**SkeletonStatus** (`prisma/schema.prisma`)
- `UNCONFIRMED` - Generated but not reviewed
- `CONFIRMED` - Designer confirmed as product/label
- `DISMISSED` - Designer dismissed/ignored

**SkeletonCreatedBy** (`prisma/schema.prisma`)
- `AI` - Generated by AI/CV system
- `HUMAN` - Created manually by designer

### Project Model Updates

**Added Fields**:
- `intent ProjectIntent @default(PAST)` - Project timeline classification
- `livingEnabled Boolean @default(true)` - Global toggle for living features (can be overridden per project)
- `livingOptOut Boolean @default(false)` - Designer-controlled opt-out per project

**New Relations**:
- `skeletonItems SkeletonItem[]` - All skeleton items for this project

### New Model: SkeletonItem

**Table**: `skeleton_items`

**Fields**:
- `id String @id @default(cuid())`
- `projectId String` - Foreign key to Project
- `projectImageId String` - Foreign key to ProjectImage
- `roomName String?` - Optional room name (string-based, aligns with ProjectImage.room)
- `bbox Json` - Normalized bounding box `{x, y, w, h}` (0-1 normalized coordinates)
- `label String` - Label from model or "unconfirmed"
- `confidence Float @default(0)` - Model confidence score (0-1)
- `status SkeletonStatus @default(UNCONFIRMED)`
- `createdBy SkeletonCreatedBy @default(AI)`
- `confirmedProductId String?` - If confirmed as product, references Product.id
- `confirmedLabel String?` - If confirmed as label (free text)
- `createdAt DateTime @default(now())`
- `updatedAt DateTime @updatedAt`

**Relations**:
- `project Project @relation(...)` - Parent project (CASCADE delete)
- `projectImage ProjectImage @relation(...)` - Image where skeleton was detected (CASCADE delete)
- `product Product? @relation("SkeletonItemProduct", ...)` - If confirmed as product (SET NULL on delete)

**Indexes**:
- `@@index([projectId, projectImageId, status])` - For efficient querying by project/image/status

### ProjectPost Model Updates

**Added Fields**:
- `dynamicHeroUpdatedAt DateTime?` - Timestamp when heroAssetId was last updated by room gravity system (prevents too-frequent updates)

### ProjectImage Model Updates

**New Relations**:
- `skeletonItems SkeletonItem[]` - Skeleton items detected on this image

### Product Model Updates

**New Relations**:
- `skeletonItems SkeletonItem[] @relation("SkeletonItemProduct")` - Skeleton items confirmed as this product

## Feature Flags

### Environment Variables (with safe defaults OFF)

All flags use `NEXT_PUBLIC_` prefix for client-side access:

- `NEXT_PUBLIC_FOLIO_LIVING_PROJECTS` - Enable living project features globally
- `NEXT_PUBLIC_FOLIO_SKELETON_TAGS` - Enable skeleton tag generation
- `NEXT_PUBLIC_FOLIO_ROOM_GRAVITY` - Enable room gravity computation
- `NEXT_PUBLIC_FOLIO_DYNAMIC_FEED_ENTRY` - Enable dynamic hero asset updates

### Per-Project Toggles

- `Project.livingEnabled` (default: true) - Per-project override
- `Project.livingOptOut` (default: false) - Designer-controlled opt-out

**Feature Gate Logic**: Feature is enabled if:
1. Global env flag is enabled
2. `Project.livingEnabled === true`
3. `Project.livingOptOut === false`

## Skeleton Items System

### Generation Pipeline

**Trigger**: On image upload/creation (via `ensureSkeletonItemsForImage()`)

**Conditions**:
- `Project.intent === PAST`
- `NEXT_PUBLIC_FOLIO_SKELETON_TAGS === "true"`
- `Project.livingEnabled === true`
- `Project.livingOptOut === false`

**Behavior**:
1. Check if skeleton items already exist for image (status: UNCONFIRMED or CONFIRMED)
2. If none exist, generate 3-8 SkeletonItem rows
3. Use deterministic bbox generation (seeded RNG based on projectImageId)
4. Labels: "unconfirmed" (can be replaced with real model labels later)
5. Confidence: Random between 0.35-0.65 (plausible range for stub data)

**Files**:
- `src/lib/living/skeleton.ts` - Core generation logic

### Confirmation Flow

**Designer Action**: Click skeleton box in editor overlay

**Options**:
1. **Confirm as Product** - Search existing products, link to Product
2. **Confirm as Label** - Free text label
3. **Dismiss** - Mark as dismissed

**Confirmation Behavior**:
1. Create `ProjectProductTag` row:
   - `projectId` from skeleton
   - `projectImageId` from skeleton
   - `productId` if product selected (else null)
   - `x`, `y` set to bbox center: `x: bbox.x + bbox.w/2, y: bbox.y + bbox.h/2`
   - `roomName` from skeleton if present
   - `notes`: "confirmed from skeleton"
2. Update `SkeletonItem`:
   - `status = CONFIRMED`
   - `confirmedProductId` or `confirmedLabel` set

**Dismiss Behavior**:
- Update `SkeletonItem.status = DISMISSED`

**API Routes**:
- `POST /api/living/skeleton/confirm` - Confirm skeleton as product/label
- `POST /api/living/skeleton/dismiss` - Dismiss skeleton
- `GET /api/living/skeleton?projectImageId=...` - Get skeletons for image

**Security**: All routes require project ownership/admin access.

## Room Gravity System

### Computation Logic

**File**: `src/lib/living/gravity.ts`

**Function**: `computeProjectRoomGravity(projectId: string)`

**Inputs**:
- `ProjectImage` records grouped by `room` string field
- `ProjectProductTag` records filtered by `roomName` or image room

**v1 Scoring Formula** (intentionally simple):
```
score = imageCount * 1.0 + confirmedTagCount * 2.0
```

**Output**:
```typescript
Array<{
  roomName: string;
  score: number;
  heroImageId?: string; // First image ID in that room
}>
```

**Function**: `pickFeatureRoomForProjectPost(projectId: string)`

**Behavior**:
- Only runs if `NEXT_PUBLIC_FOLIO_ROOM_GRAVITY` enabled
- Only runs if `Project.livingEnabled === true` and `Project.livingOptOut === false`
- Calls `computeProjectRoomGravity()`
- Selects highest-score room
- Returns: `{ heroAssetId?: string, roomName?: string }` or `undefined`

**Hero Image Selection**:
- Uses first `ProjectImage` in selected room (by creation order)
- Falls back to any available image if room has no images

## Dynamic Feed Entry Image

### Update Logic

**File**: `src/lib/living/applyDynamicHero.ts`

**Function**: `applyDynamicHeroForProject(projectId: string)`

**Behavior**:
1. Load `ProjectPost` for project
2. If post `status !== "PUBLISHED"`, return early
3. If `NEXT_PUBLIC_FOLIO_DYNAMIC_FEED_ENTRY` disabled, return early
4. Call `pickFeatureRoomForProjectPost(projectId)`
5. If returns `heroAssetId`:
   - Check `ProjectPost.dynamicHeroUpdatedAt`
   - If updated within last 7 days, skip (guardrail)
   - Otherwise update `ProjectPost.heroAssetId = heroAssetId`
   - Update `ProjectPost.dynamicHeroUpdatedAt = now()`
   - Optionally write to `expandedBlocks.living = { featureRoomName, updatedAt }`

**Triggers**:
- Manual: `POST /api/admin/living/apply-dynamic-hero?projectId=...`
- Automatic: After skeleton confirmation (since it changes room tag richness)

## Safety Guarantees

### Public Page Protection

**Rule**: Skeleton items are NEVER queried on public pages.

**Implementation**:
- Skeleton queries only in authenticated project owner/admin contexts
- No skeleton data in public API responses
- No skeleton rendering in public project views

### API Route Protection

**Rule**: All skeleton/dynamic hero routes require project ownership or admin role.

**Implementation**:
- Check session ownership via `Project.ownerId` or `Project.designerId`
- Check admin role via `User.role === "ADMIN"`
- Return 403 Forbidden if unauthorized

### Error Handling

**Rule**: Skeleton generation failures must never block image upload.

**Implementation**:
- Wrap `ensureSkeletonItemsForImage()` in try-catch
- Log errors but do not throw
- Upload completes successfully even if skeleton generation fails

## Migration Notes

1. Run Prisma migration: `npx prisma migrate dev --name add_living_project_system`
2. Regenerate Prisma client: `npx prisma generate`
3. Set feature flags in `.env` (all default to OFF for safety)
4. Existing projects will have `intent = PAST`, `livingEnabled = true`, `livingOptOut = false` by default
5. Existing `ProjectPost` records will have `dynamicHeroUpdatedAt = null`
