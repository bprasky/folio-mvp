## What the connected test proves

- Signup and manual creation are driven through rendered controls and real credential/session exchange. Onboarding, photo/room/tag/interview and lifecycle operations use authenticated browser `fetch` through the actual Next API, followed by PostgreSQL and rendered-page assertions. They are not route-module mocks, but this does **not** claim every intermediate form was clicked in the connected run. Actual component interaction suites cover those controls separately.
- Local PostgreSQL is native 18.6 with pgvector 0.8.1 in an isolated Alpine chroot under the available WSL Docker Desktop distribution. No working Docker daemon was assumed. Redis 8.4.2 executes the actual rate-limit scripts; a test HTTP adapter translates the Upstash REST boundary. No production rate limit was disabled.
- Storage uses actual files and HTTP with Supabase-compatible requests. Its policy code is synthetic. AI uses the actual SDK against a loopback response fixture; generated prose is deterministic. Email credentials are absent and test products have no vendor recipients. A preload blocks non-loopback application network access.
- Approval/publication uses an isolated administrator account and the real lifecycle. Owner publication of a REVIEW post is refused (409); administrator approval/replay succeeds. Anonymous draft/public/unpublished rendering and actual byte access are checked. Next may stream a not-found page with HTTP 200; the test asserts no private title in HTML and API denial instead of pretending status alone proves privacy.
- Viewport/touch checks are Chrome emulation and simulated touch, not physical iOS Safari/Android testing. See [screenshots](screenshots/) and individual result manifests. Long titles/answers, many photos, short dialogs, loading/empty/error/success, keyboard, focus, reduced motion and touch targets are represented in the responsive fixtures.
